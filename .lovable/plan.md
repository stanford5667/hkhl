

## Affiliate Discount Code Issues -- Diagnosis

I found **three problems** in the affiliate discount flow:

### Problem 1: Case mismatch between storage and lookup
In `useAffiliateTracking.tsx` (line 31), the affiliate code from the URL (`?ref=XXXX`) is stored in localStorage **as-is** (preserving original case). But in `create-checkout/index.ts` (line 70), it's converted to **uppercase** via `.trim().toUpperCase()`. Meanwhile, in the database, the `affiliate_code` column stores codes as generated by `generate_affiliate_code()` which uses `upper()`. If a user manually enters a code at checkout in lowercase, the `.toUpperCase()` call fixes it. But when stored via the `?ref=` URL flow, the code in localStorage retains whatever case the URL had, which is fine since it gets uppercased at checkout. **This part is actually OK.**

### Problem 2: Stripe `discounts` vs `allow_promotion_codes` conflict
When the affiliate code is found and has a `stripe_promo_code_id`, the code sets:
```
sessionParams.discounts = [{ promotion_code: affiliateData.stripe_promo_code_id }];
```
Stripe requires using **either** `discounts` **or** `allow_promotion_codes` -- never both. This part is handled correctly (they're in separate branches). **This is OK.**

### Problem 3 (REAL ISSUE): The `discounts` param uses `promotion_code` ID but Stripe expects a Promotion Code ID, not a Coupon ID
On line 174, the code does:
```js
sessionParams.discounts = [{ promotion_code: affiliateData.stripe_promo_code_id }];
```
The `stripe_promo_code_id` stores the Stripe **Promotion Code** object ID (e.g., `promo_xxx`). The Stripe Checkout `discounts` array accepts either `{ coupon: "coupon_id" }` or `{ promotion_code: "promo_xxx" }`. This should work IF the stored value is indeed the promotion code ID. Let me verify -- in `create-affiliate-promo/index.ts` line 76-84, it saves `promoCode.id` which IS the promotion code object ID (`promo_xxx`). **This should work.**

### Problem 4 (REAL ISSUE): Affiliate promo codes may not have been created yet
The `create-affiliate-promo` function is called manually to create a Stripe promo code for an affiliate. If this was never called for the affiliate, `stripe_promo_code_id` will be **null**, and the checkout falls through to `allow_promotion_codes = true` (manual entry). But then the user needs to **manually type** the code at Stripe checkout -- they won't see any automatic discount.

### Problem 5 (MOST LIKELY ISSUE): The `?ref=` URL flow stores the code but it may never reach checkout
Looking at `getAffiliateRef()` in `useAffiliateTracking.tsx` and `useUpgrade.tsx`:
- `getAffiliateRef()` reads from localStorage and returns the code
- `startCheckout()` passes it as `affiliate_code` to the edge function
- The edge function looks up the affiliate by code and applies the discount

**The flow is correct in theory.** So the likely problem is one of:

1. **The affiliate doesn't have a Stripe promo code created** (`stripe_promo_code_id` is null) -- so no automatic discount is applied, and users must manually enter the code
2. **The promo code exists in Stripe but is inactive/expired**
3. **The localStorage data expired** (90-day window) or was cleared

---

## Recommended Fix

### Step 1: Add auto-creation of Stripe promo code on affiliate approval
When an affiliate is approved, automatically call `create-affiliate-promo` so every approved affiliate always has a working Stripe promo code.

### Step 2: Add error logging to surface the exact failure
Add a toast or console log when the affiliate code lookup fails silently at checkout, so we can see exactly what's happening.

### Step 3: Validate the promo code exists before checkout
In `create-checkout`, after looking up the affiliate, verify the Stripe promo code is still active by calling `stripe.promotionCodes.retrieve()`. If it's been deleted or deactivated in Stripe, recreate it.

### Files to modify:
- `supabase/functions/create-checkout/index.ts` -- Add promo code validation and auto-creation fallback
- `supabase/functions/create-affiliate-promo/index.ts` -- Minor: make it idempotent
- Optionally: database trigger on `affiliates` table status change to auto-create promo
